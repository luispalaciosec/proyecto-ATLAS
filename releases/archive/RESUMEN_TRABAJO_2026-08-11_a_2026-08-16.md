## 1. Bugs de Conocimiento y Chat (13 ago)

### Bug #1 — Contexto obsoleto en preguntas repetidas

**Síntoma:** Tras subir un documento nuevo, repetir la misma pregunta en el mismo hilo devolvía la respuesta antigua (“no tengo esa política”), aunque el documento ya estaba indexado. Solo funcionaba si se pedía explícitamente “revisa Conocimiento”.

**Causa:** El LLM no re-ejecutaba búsqueda fresca en turnos repetidos; reutilizaba razonamiento previo del historial.

**Fix (`0c7bf5e`):**
- Prefetch de conocimiento fresco en cada turno LLM (`session-store.ts`, `llm-module.ts`).
- Instrucciones de sistema reforzadas para re-consultar Conocimiento ante preguntas repetidas o mención de contenido actualizado.
- Tests de regresión en `server.test.ts`, `llm-module.test.ts`.

### Bug #2 — Búsqueda en Conocimiento no filtraba

**Síntoma:** Query `descuento` devolvía los 5 documentos de la marca, incluidos los que no contenían el término.

**Causa:** Query vacía o matching demasiado laxo en el pipeline de búsqueda.

**Fix (`0c7bf5e`):**
- Query vacía → `total: 0` (no devolver todo el corpus).
- Token matching más estricto en `memory-module.ts`.
- Tests en `memory-module.test.ts` y `server.test.ts`.

### Limpieza posterior (`fce1f93`, `e87c3d0`)

Al mergear el fix, quedaron referencias rotas a métodos de biblioteca/carpetas que aún no estaban completos. Se limpiaron imports incompletos y se restauró un test de upload para mantener `main` verde sin arrastrar WIP roto.

**Archivos tocados:** `apps/web/src/session-store.ts`, `apps/web/tests/server.test.ts`, `packages/sdk/src/modules/llm-module.ts`, `packages/sdk/src/modules/memory-module.ts`, tests asociados.

## 3. Excel Knowledge — Parte B (14 ago)

### Objetivo

Permitir subir hojas de cálculo `.xls` y `.xlsx` como fuente de Conocimiento, con chunking por filas, contexto de hoja/headers, y búsqueda usable desde la UI y el chat.

### Implementación (`dedfcfa`)

| Componente | Detalle |
|------------|---------|
| **Dependencia** | `xlsx@^0.18.5` (SheetJS CE) solo en `@atlas/web` |
| **`extract-excel.ts`** | Parser multi-hoja; fechas; fórmulas (valor cacheado); validación firma binaria |
| **`chunk-excel.ts`** | Chunks por filas con prefijo archivo/hoja/headers; metadata `rowStart`/`rowEnd` |
| **`session-store.ts`** | Rama Excel antes de `chunkText`; respuesta con `sheetCount` |
| **UI / i18n** | Extensiones XLS/XLSX, fase “Leyendo hojas de cálculo…”, mensajes enriquecidos |
| **Tests** | Unit (`extract-excel`, `chunk-excel`) + integración HTTP (`server`, `knowledge-upload`) |

**Gobernanza:** `packages/*` kernel frozen — **sin diff**. Motion System fuera de alcance.

### Fix post-auditoría — búsqueda de valores pegados

**Bug encontrado en verificación independiente:**

Filas indexadas como `Producto=Taladro` (sin espacio). El tokenizador (`tokenizeForSearch`) divide solo por espacios → `Taladro`, `45000`, `Ferreteria` **no encontrables**; solo la segunda palabra de valores multi-palabra (`Andina`, `Loja`).

**Fix:** Formato `Header: valor` en `formatDataRow`:

```typescript
parts.push(`${header}: ${value.length > 0 ? value : ''}`);
```

**Verificación en vivo (repro exacto):**

| Query | Antes | Después |
|-------|-------|---------|
| `Ferreteria` | 0 | 1 ✅ |
| `Taladro` | 0 | 1 ✅ |
| `45000` | 0 | 1 ✅ |
| `Comercial` | 0 | 1 ✅ |
| `Sierra` | 0 | 1 ✅ |

## 4. Fix UI file picker Excel (16 ago) — pendiente de commit

**Síntoma reportado:** En `/conocimiento`, el diálogo de macOS mostraba `.xls` y `.xlsx` en gris; solo PDFs seleccionables.

**Causa:** El `<input type="file">` tenía `accept=".pdf,.docx,.pptx,.txt,.md"` hardcodeado, aunque `SUPPORTED_UPLOAD_EXTENSIONS` ya incluía Excel.

**Fix aplicado (local, sin commit):**

```typescript
const SUPPORTED_UPLOAD_ACCEPT = SUPPORTED_UPLOAD_EXTENSIONS
  .map((ext) => `.${ext}`)
  .join(',');
// → ".pdf,.docx,.pptx,.txt,.md,.xls,.xlsx"
```

**Archivo:** `apps/web/src/client/pages/knowledge.ts`  
**Acción pendiente:** commit + push cuando se autorice.
